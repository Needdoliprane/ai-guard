# Owned human sources: local identity and resources

This explicit gateway mode reopens an existing complete owned source union. The default remains `legacy`. The [dated software validation](../../engineering/evidence/2026-11-13/human-sources-operator/README.md) covers local adoption and the two adopted reads on an identified Linux ARM64 source; it does not qualify production, a worker runtime or OIDC.

Use the [offline source adoption procedure](../human-sources-maintenance/README.md) to prepare the private metadata/envelope, migrate the union and publish the real closure manifest and gateway activation. Its five commands are `human-sources prepare`, `resume-prepare`, `apply`, `resume` and `check`. Adoption requires an existing tenant registry and Store13 databases, plus Auth4, OIDC configurationV2 and its explicit public trust bundle when OIDC is selected. The coordinator converts the complete union from Store13 to14 and Auth4 to5; ordinary single-database migrations still stop at Store13/Auth4. Provision named people, credentials and grants before conversion using the [legacy identity procedure](README.md); source adoption creates none of them. Do not hand-author receipts, initialize replacement databases, increase accepted versions or use test fixtures as an installation procedure.

After `apply` or `resume` publishes the complete activation, use it for normal startup in the existing containerized gateway launch:

```text
gateway --human-sources-activation /control/human-preparation/activation.json
```

Retain the installation's actual HTTP binding, server TLS and decision settings. Do not combine activation with direct source, registry, credential, revision, capacity, initialization or OIDC options. The gateway reconstructs and replays the real source union on every startup; the activation files alone do not prove source readiness. Stop all consumers before preparation or migration: `--confirm-control-stopped` is a manual attestation, without legacy-process fencing. Preserve sources, private preparation, journal, backups and matching configuration in place after interruption, then use the matching resume step in the adoption guide. `check` validates files/metadata only, without checking SQLite, authentication or readiness.

The direct options below remain available for an installation whose retained manifest/envelope were produced through the real owned migration protocol. Use them as an alternative to activation, retaining its actual policy, data mounts, event limit and other options:

```text
gateway --human-source-mode owned_sources
  --tenants-file /control/tenants.json
  --human-sources-manifest /control/existing-closure.json
  --human-credentials-envelope /control/existing-technical-credentials.json
  --human-control-config-revision <actual-positive-control-revision>
```

These are references to existing private files, never tokens in arguments. The manifest and envelope are not generated by startup. The tenant registry supplies effective quotas and policies. The loader independently resolves defaults and recalculates the version1 public configuration digest, excluding credentials, their digests and private paths; physical bindings are compared separately. Use the revision retained by the operator, not a value guessed from an error. An OIDC installation also requires its existing `--oidc-config` and explicit `--human-oidc-mapping-revision`; that positive closure revision is distinct from the string `mapping.revision`. Missing/changed files, limits, revisions, formats or union refuse startup. Initialization flags conflict with this mode. Preserve all files and known commits on failure; startup performs no migration, reset or legacy fallback.

Use the matching trusted dashboard launch profile:

```text
dashboard --shared-tenants --human-source-mode owned_sources
  --upstream http://gateway:8787 --front-dir /app/front
```

Keep the installation's actual internal upstream and static directory. A viewer-file fallback conflicts with this profile. Gateway authorization remains authoritative even if presentation is misconfigured. For the dashboard API proxy routes, modern HEAD requests are refused before viewer verification or conversion to GET. The gateway health route retains GET/HEAD; it is separate from the control diagnostic.

The admitted human credential is the already provisioned private local bearer. The first `human identity` GET is its connection check; no password/login endpoint is introduced. Use the existing [identity/resources commands](README.md#read-from-the-cli), passing `--credential-file` privately and a context actually returned by identity. The basic human reads include `GET /api/v1/human/identity`, `GET /api/v1/human/resources`, `GET /api/v1/human/events` and `GET /api/v1/human/events/recent`. Both event lists are metadata-only. The identity response describes the authenticating source; with other tenant sources, `contexts_complete=false` means their memberships remain unknown. Cross-source context selection is refused. A resource page carries its real durable `read_receipt`; a candidate digest never supplies identity, permission or a receipt.

For the exact event detail, use `GET /api/v1/human/events/{id}?view=metadata` with the canonical lowercase, hyphenated event UUID and an offered `X-AiGuard-Context`. This read covers owned SQLite Stores 14 and 15. It uses the same authenticated source, authorization epoch and metadata permissions as the list, including access to the event's resource. A successful response contains one metadata item and a durable `read_receipt` for audit action `event`. With the gateway and dashboard on the same version, open **Métadonnées** (Metadata) for the authorized resource in **Ressources**, then **Détails** (Details) for the event in **Événements**.

**Vue 360°** opens in an administration context and **Mon espace** in a personal context when the catalogue lists `summary_read` as granted and available. The read uses the retained local Store 14 or 15 with the human rights marker and requires durable audit. With `read_worker_registry` in the administration context, the workers section shows durable states and reservations. Runtime inventory is `unknown`. With the same administration right, the quota and usage sections show the durable reservations and the observed allocations ending in the chosen period. All sections share the summary receipt.

The Journal's recent read is metadata-only. A successful page with `stream_mode:"snapshot_only"` and `live_cursor:null` identifies this current owned profile; the marker grants no permission and says nothing about another server/profile. Older-page cursors retain their authorized selection and fixed descending bound. The UI shows the actual read time and receipt of the last page read. Live updates, content and export are unavailable for this profile. The catalogue reports `profile_unavailable` for `events_read_content`, `events_export` and `events_stream` even when the corresponding permission is granted. After a successful Journal page identifies this profile, Content (Contenu) and Export (Exporter) explain this profile limit and are disabled; the granted permissions remain unchanged.

Use **Actualiser** (Refresh) to read recent events again. The Journal opens no stream, retry loop or periodic polling; returning to the tab retains the normal one-time revalidation. A failed revalidation withdraws displayed snapshot data, receipts and pagination positions. A transient error in the same context keeps the previously established restrictive profile; an identity/context/authorization change or session close clears that fact. A503 never establishes another profile. An explicitly refused content request remains an error with an explicit route back to Resources; there is no silent metadata fallback. Update gateway and dashboard together. The dated software evidence at the start of this guide retains its original two-read scope.

Known unadopted human, control, workload, broker, relay and OIDC methods, including HEAD on the event detail route, export and stream, return explicit 503 coverage refusals before legacy extractors, body handling or Store work. OIDC selected in the manifest remains selected and retained, while its handlers/bearers are closed. It is never reported as disabled. Only when OIDC is absent are the existing disabled status/profile GETs admitted. Health reads memory state; it is not proof that every source is available. These reads enable no modern approval, launch, network permission or egress control.

The local Administration context can read `GET /api/v1/human/workers` on SQLite 14 and 15 with `read_worker_registry`. Identity announces `worker_registry:"human_worker_registry_owned_v1"`. Every page carries a durable receipt from the authenticated source. The dashboard shows the authorized Workers view and its read time. The federation route is unavailable on this profile. [Worker registry](../supervision/README.md#owned-broker-supervision-profile)

The local administration context can read `GET /api/v1/human/admin/quota` and `GET /api/v1/human/admin/usage` when the catalogue grants and serves their operations. **Quotas et usage** reads the configured limits and durable reservations first, then the page of observed terminal allocations. Each available section shows its own read time and receipt. Allocations carry `billable:false`. A missing terminal observation leaves the duration unknown.

**Utilisateurs** offers **Modifier** for another existing membership when the Administration context grants `memberships_manage`. The dashboard sends the change to a gateway configured for owned sources. After a lost response, refresh your access and select **Reprendre la même modification**. The durable receipt confirms the outcome. [POST contract](../../api.md#changement-délégué-dappartenance--delegated-membership-change)

**Resources** offers **Gérer les partages** (Manage shares) for a resource bound by the operator when the administration context grants and serves `grants_manage`. After an unknown outcome, refresh your access and choose **Réessayer la même opération** under an equivalent context. The receipt confirms the share revision and audit position. [Delegated shares contract](../../api.md#partages-délégués--delegated-shares)

Event content, export, stream and other administration writes through the dashboard remain required for V1.

A busy mutex or SQLite writer in sourceA does not trigger SQL queries in A while authenticating and reading sourceB. A busy own source returns503. Busy is not absence or a permanent mismatch. Actual compared filesystem/configuration/marker/incarnation mismatches retain global owner invalidation. Filesystem revalidation still covers the full union: blocked filesystem calls or a shared Write epoch carry the existing availability limits. The private candidate index is bounded at65536 entries/16MiB of representation before accumulation; overflow refuses complete publication. These bounds do not measure process RAM.

For the adopted human reads, runtime compares the own source's real identity authorization revision and workload-binding-history high watermark before and after the adopted operation. These markers cover identity mutations and workload-binding issue/rotation/revocation; ordinary read audits do not move them. A compared mismatch requires discovery rebuilding with admission closed. This is not a universal writer generation: identity/workload HTTP writers remain closed, and a raw neighboring storage mutation cannot be detected instantly without observing that neighbor.

The human-metadata validation already linked in this guide keeps its original source and scope; it is not A0 evidence. Existing startup commands and configuration files above are unchanged.

The candidate adopts only the existing exact GET `/control/api/v1/control/protocol` on the reserved transport, with no query or new startup flag. It requires a real technical `runner` entry in the retained `ReviewCredentialRegistry`, a unique technical candidate in the complete startup index and the real binding/source/namespace/generation. A named human bearer, a viewer, a workload credential, `HumanSourceAccess` or a DTO cannot supply that actor identity. Public GET `/api/v1/control/protocol`, HEAD on this diagnostic and known owned mutations remain closed; unknown paths/methods keep 404/405.

The checked `Business` transaction verifies the binding before facts and revalidates it before commit on the selected Store. Credential, source and epoch are revalidated before publication. Accepted usage and operation/IO permits stay with the real work until it finishes, including after the HTTP future is abandoned; this behavior is covered by the targeted software validation. Own-source contention refuses without waiting; the previous SQLite timeout is restored, with no neighboring SQL or legacy fallback. A0 provisions no credential or binding and adds no operator command, service, SQLite format, audit record or receipt.

The candidate Rust validator and JSON Schema agree on the existing `ControlProtocolV1` facts for formats 14/15; `active` remains the actual lease fact. A future 200 from `AuditClient::control_supervision_identity` would qualify neither broker lifecycle nor a connection permit. The broker 3–13 and relay 6–13 gates stay unchanged; 14/15 still encounter `IncompatibleControl` before broker effects. No worker, human launch or egress capability is opened.

Coverage is the complete W0 startup index plus the selected source's own generation, not multiprocess coherence or a universal writer generation. Within the inspected A0 source boundary, owned HTTP writers remain closed. Candidate A1 below connects only policy-registry replace/revoke; internal identity/workload source/`WriteEpoch` writers still have no post-startup server caller. A future writer changing credentials, workloads or candidate coverage must close admission through `require_rebuild` **before the effect**, then reconstruct the complete union. A B read cannot infer a new A collision without a global invalidation producer; the real own binding is nevertheless checked on each diagnostic. See the [candidate API contract](../../api.md#owned-control-a0). These are limits to preserve before adopting any writer, not a new end-user procedure.

The server reserves a cleanup supervisor before fallible builders/binds. Shutdown and Drop close human/context admission, stop HTTP, observe real HTTP joins, and wait for accepted/queued blocking usages and epochs. A drain error reports failure, including any primary bind/serve error. An unestablished drain is never success; real remaining usage/epoch handles retain their owner and file descriptors. Runtime/process termination and host failure remain outside this in-process guarantee.

Local browser `HumanApiClient.close()` clears the token, aborts requests and discards late responses. It does not revoke the durable credential. Modern credential mutation, fresh discovery of memberships from other sources and SSO sessions/revocation remain mandatory open work. The adoption workflow records its software results and [remaining qualification limits](../human-sources-maintenance/README.md#validation-scope). Stop consumers and retain configuration, databases, backups and evidence before operator reconciliation; never delete history to recover a green startup.

## A1: inspect and prepare policy-registry operations

The [inspection and internal CLI evidence](../../engineering/evidence/2026-11-14/owned-policy-inspection/README.md) verifies the composed path on `45179db`; the report remains historical and the server rechecks the final mutation. This is local software evidence, without an AI client, model, worker or network-enforcement qualification.

Use `broker policy inspect` to retain the actual scope and policy metadata, then prepare a request locally from that report. Registry operations remain `policy_registry_only`; inspection has the narrower `policy_registry_metadata` coverage. A report, durable policy or `revoke_requested` receipt is neither human approval nor evidence of network filtering, a connection permit, or worker/broker execution. The [earlier dated A1 software evidence](../../engineering/evidence/2026-11-14/owned-egress-policy-api-cli/README.md) retains its exact source and scope; it does not qualify another source or production deployment.

### Prerequisites these commands do not create

Use an already adopted owned installation with **actual Store15**, a retained complete source union, and a technical runner credential already present in its private registry **with an active binding to that exact source/tenant/namespace**. A named human bearer, viewer, workload token or SSO role is not this credential. These commands provision no account, credential, binding, Session or worker and perform no migration. The adoption procedure above converts 13→14, not15; the separate [E1 maintenance contract](../../engineering/EGRESS_POLICY_STORE.md#exact-format-15-and-maintenance) describes the existing trusted maintenance protocol. Do not manufacture envelopes, receipts or SQLite rows, or use test fixtures as an installation procedure. Stop here and retain the installation files if these prerequisites are unavailable.

Keep the runner token and draft/full-envelope input files private (0600), outside the user workspace, frontend and public artifacts. Each output needs an existing private parent (0700) and a **new absent destination**. Keep report and operation directories separate; an operation cannot be prepared inside its report, including through a physical case/Unicode alias. Final names are at most 128 ASCII alphanumeric/dot/dash/underscore characters, excluding `.` and `..`. Paths and ancestors are checked without following arbitrary links; no file, permissions or existing directory is silently repaired.

**Set the variables below to the installation's actual nonsecret origin and private paths before running a command.** `GATEWAY_ORIGIN` is HTTPS or HTTP loopback, with no URL credential, query, fragment or non-root path. `PRIVATE_RUNNER_TOKEN` names the private file, never its contents. `SESSION_ID`, when selected, is the actual canonical nonnil Session UUID. The credential determines the tenant; neither selector chooses another tenant.

### Inspect one policy selector

Choose one of these alternatives, with a new `NEW_INSPECTION_DIR`:

```sh
agentsandbox broker policy inspect --gateway "$GATEWAY_ORIGIN" --token-file "$PRIVATE_RUNNER_TOKEN" --tenant --output-dir "$NEW_INSPECTION_DIR"
```

```sh
agentsandbox broker policy inspect --gateway "$GATEWAY_ORIGIN" --token-file "$PRIVATE_RUNNER_TOKEN" --session "$SESSION_ID" --output-dir "$NEW_INSPECTION_DIR"
```

Exactly one of `--tenant` and `--session` is required. Inspection makes one explicit reserved metadata POST; it submits no replacement/revocation. It validates the response and revalidates the private token around the request and durable publication. Success prints only version, kind, observed_at, historical:true and coverage:policy_registry_metadata. It is not a full policy read or a current runtime view.

The private report has exactly four entries: `request.json` (canonical selector request), `metadata.json` (`version:1`, `kind:"policy_inspection"`, gateway and request/observation SHA-256), `current.json` (canonical observation), and `owner.lock`. Records are 0600 and the directory 0700. Its gateway is the validated canonical origin **without the single root-path slash**; reopening requires that exact form. Derived A1 operation metadata still uses its existing origin normalization. The report accepts no pending state or receipt and cannot be used as an apply/resume/status operation directory.

`current.json` records the actual authenticated scope, requested selector, an explicitly absent/present policy head, tenant ceiling metadata for Session, the current identity-resource flag, and the control's observed_at. `session_resource` is a **string**: `"not_applicable"` for Tenant, otherwise `"active"`, `"inactive"` or `"absent"`. Registry states do not establish interval eligibility or effective permissions; the resource flag is not runtime status. See the [exact API fields](../../api.md#owned-policy-inspection).

The observation is dated, historical, unsigned and editable by its local owner. Hashes correlate local bytes; they do not authenticate a permission or guarantee freshness. A healthy checked source/audit is required, but inspection creates no per-read audit event or receipt. Unknown, busy or damaged source data never becomes an absent head. Another operation may change the head or namespace immediately after inspection.

### Author a closed draft and prepare locally

A replace draft contains only version, action and policy. **This is a template: replace both null time fields with an explicitly chosen valid Unix-millisecond window before use.** Expiry follows not-before; the server's durable clock and policy rules remain authoritative. The empty destination list expresses a deny-all registry policy, not network access.

```json
{
  "version": 1,
  "action": "replace",
  "policy": {
    "not_before_ms": null,
    "expires_at_ms": null,
    "destinations": [],
    "max_destinations": 128,
    "max_resolution_ips": 16
  }
}
```

A revoke draft has no policy or time window:

```json
{
  "version": 1,
  "action": "revoke"
}
```

Save the selected draft privately, then prepare a **new** operation:

```sh
agentsandbox broker policy prepare --inspection-dir "$NEW_INSPECTION_DIR" --input "$PRIVATE_DRAFT_JSON" --output-dir "$NEW_OPERATION_DIR"
```

Preparation is local only and holds the report lock throughout. It copies origin, scope and selector from the report, uses 0/0 **only for an explicitly absent head**, otherwise retains the exact revision/epoch, and generates one UUID for this new local request. A replacement may use a present `revoke_requested` head with its actual CAS. A Session replacement requires both an active identity resource and active tenant ceiling, and copies its exact revision/epoch/digest. Revoke requires an active target head; inactive/absent resource or ceiling and the former policy's time window do not block local cleanup preparation. Final A1 authority, scope/CAS and applicable clock checks remain mandatory at submission. Revocation does not require an active Session resource/tenant ceiling or an unexpired former policy.

The draft accepts no `operation_id`, `scope`/`expected_scope`, `selector`, CAS, ceiling, request envelope or unknown field. Input is capped at 66,560 bytes; canonical request at 65,536; report observation, local metadata/state and receipt at 4,096 each; token file at 4,096. Report hashes, canonical shape, selector and origin are checked, and report/draft/ancestors are revalidated around publication. A failed local check does not repair, overwrite or delete evidence.

### Submit, read local history and explicitly resume

```sh
agentsandbox broker policy apply --operation-dir "$NEW_OPERATION_DIR" --token-file "$PRIVATE_RUNNER_TOKEN"
agentsandbox broker policy status --operation-dir "$NEW_OPERATION_DIR"
agentsandbox broker policy resume --operation-dir "$NEW_OPERATION_DIR" --token-file "$PRIVATE_RUNNER_TOKEN"
```

apply requires the initial prepared state. It holds the local lock, revalidates files/token, compares a real reserved diagnostic to the prepared scope, durably records intent and attempts the prepared action once. The final A1 transaction checks the authenticated scope and current CAS again, plus the ceiling for Session replacement. There is no hidden inspection, origin/scope/CAS override, automatic retry, new UUID, redirect/proxy or public/legacy fallback. SDK bounds remain 15 s/request and 3 s/connect. Format 14 requires explicit maintenance.

status is local historical evidence, not a server-head fetch. Its JSON retains operation_id, action, phase, attempts, last_error, receipt_present, pending_state and receipt summary, with historical:true and coverage:policy_registry_only. Phases are prepared, remote_outcome_unresolved and receipt_recorded; attempts counts local intents, not remote effects. It prints no token, actual scope, origin, DNS, private path or runtime_applied claim. An incomplete/unsafe record is an error, never empty history.

resume preserves the exact UUID and request bytes. It may publish an already retained validated local pending transition; reopen/status never repair it implicitly. An existing canonical action-correlated receipt is revalidated/resynchronized and returned as history without another POST or new server observation. Otherwise resume performs a new reserved diagnostic and at most one same-operation POST. Accepted work may finish after observer loss; lost ACK, timeout, token change, transport/invalid-response error or local publication/output failure is not proof of rollback. Preserve every record, including partial/unresolved evidence.

### Refusals, stale observations and compatible full-envelope preparation

| Refusal | Operator action |
|---|---|
| Missing/invalid credential, non-runner or wrong binding/source | Check the existing technical credential and owned installation. A human login/SSO role is not a substitute. |
| `egress_policy_session_resource_unavailable`, `egress_policy_tenant_ceiling_unavailable`, `egress_policy_revoke_requires_active_head` | Review the retained observation and requested action. Preparation invents no resource, ceiling or head. |
| `egress_policy_scope_conflict` / `egress_policy_conflict` (409 at final A1) | Retain report and operation unchanged. A stale observation is never repaired, refetched or retried automatically. |
| `egress_policy_migration_required` | Stop and use the separate trusted maintenance procedure; no automatic migration. |
| Busy/capacity/clock/source/audit unavailable | Retain evidence and diagnose the actual refusal. Local busy may mean another command holds the report/operation lock; it is not absence. |
| Unsafe/changed/incomplete local records, overlapping output or unresolved publication/output | Preserve files and any staging evidence. Do not edit records, relax permissions checks, remove a receipt or reuse a destination to force success. |

If current facts must be obtained after a conflict, request a **new explicit inspection**, review it, and separately decide whether to prepare a new operation in a new directory. This never rewrites or resolves an earlier ambiguous operation; retain its evidence and use matching resume when needed. The server remains authoritative even for an owner-modified but hash-consistent report. Receipt states describe registry changes: `revoke_requested` is not observed runtime closure. Error envelope details are in the [API contract](../../api.md#owned-policy-a1).

```sh
agentsandbox broker policy prepare --gateway "$GATEWAY_ORIGIN" --input "$PRIVATE_FULL_INPUT_JSON" --output-dir "$NEW_OPERATION_DIR"
```

This input is the existing closed version1/action/request envelope with its explicit operation UUID, expected_scope, selector and CAS (plus policy/ceiling for replace). See the [A1 request contract](../../api.md#owned-policy-a1). Use only actual controlled facts; do not guess scope/CAS or query SQLite as a user workaround. `--gateway` and `--inspection-dir` are mutually exclusive. A full envelope is not a draft, and neither path silently falls back to another input format. Existing operation directories remain compatible with apply/resume/status.

Filesystem barriers use retained files/locks and file, operation-directory and parent synchronization; they do not prove physical power-loss recovery. Existing same-UID/root trust limits remain. No credential mutation, full policy-content read, runtime network mediation/revocation, provider/worker/cluster qualification or broker 3–13/relay 6–13 gate opening follows from this path. Qualification evidence remains tied to its actual source and scope.
