# Owned human sources: local identity and resources

This explicit gateway mode reopens an existing complete owned source union. The default remains `legacy`. The [dated software validation](../../engineering/evidence/2026-11-13/human-sources-operator/README.md) covers local adoption and the two adopted reads on an identified Linux ARM64 source; it does not qualify production, a worker runtime or OIDC.

Use the [offline source adoption procedure](../human-sources-maintenance/README.md) to prepare the private metadata/envelope, migrate the union and publish the real closure manifest and gateway activation. Its five commands are `human-sources prepare`, `resume-prepare`, `apply`, `resume` and `check`. Adoption requires an existing tenant registry and Store13 databases, plus Auth4, OIDC configurationV2 and its explicit public trust bundle when OIDC is selected. The coordinator converts the complete union from Store13 to14 and Auth4 to5; ordinary single-database migrations still stop at Store13/Auth4. Provision named people, credentials and grants before conversion using the [legacy identity procedure](README.md); source adoption creates none of them. Do not hand-author receipts, initialize replacement databases, increase accepted versions or use test fixtures as an installation procedure.

After `apply` or `resume` publishes the complete activation, use it for normal startup in the existing containerized gateway launch:

```text
gateway --human-sources-activation /control/human-preparation/activation.json
```

Retain the installation's actual HTTP binding, server TLS and decision settings. Do not combine activation with direct source, registry, credential, revision, capacity, initialization or OIDC options. The gateway reconstructs and replays the real source union on every startup; the activation files alone do not prove source readiness. Stop all consumers before preparation or migration: `--confirm-control-stopped` is a manual attestation, without legacy-process fencing. Preserve sources, private preparation, journal, backups and matching configuration in place after interruption, then use the matching resume step in the adoption guide. `check` validates files/metadata only, without checking SQLite, authentication or readiness.

The direct options below remain available for an installation whose retained manifest/envelope were produced through the real owned migration protocol. Use them as an alternative to activation, retaining its actual policy, data mounts, event limit and other options:

```text
gateway --human-source-mode owned_sources
  --tenants-file /control/tenants.json
  --human-sources-manifest /control/existing-closure.json
  --human-credentials-envelope /control/existing-technical-credentials.json
  --human-control-config-revision <actual-positive-control-revision>
```

These are references to existing private files, never tokens in arguments. The manifest and envelope are not generated by startup. The tenant registry supplies effective quotas and policies. The loader independently resolves defaults and recalculates the version1 public configuration digest, excluding credentials, their digests and private paths; physical bindings are compared separately. Use the revision retained by the operator, not a value guessed from an error. An OIDC installation also requires its existing `--oidc-config` and explicit `--human-oidc-mapping-revision`; that positive closure revision is distinct from the string `mapping.revision`. Missing/changed files, limits, revisions, formats or union refuse startup. Initialization flags conflict with this mode. Preserve all files and known commits on failure; startup performs no migration, reset or legacy fallback.

Use the matching trusted dashboard launch profile:

```text
dashboard --shared-tenants --human-source-mode owned_sources
  --upstream http://gateway:8787 --front-dir /app/front
```

Keep the installation's actual internal upstream and static directory. A viewer-file fallback conflicts with this profile. Gateway authorization remains authoritative even if presentation is misconfigured. For the dashboard API proxy routes, modern HEAD requests are refused before viewer verification or conversion to GET. The gateway health route retains GET/HEAD; it is separate from the control diagnostic.

The admitted human credential is the already provisioned private local bearer. The first `human identity` GET is its connection check; no password/login endpoint is introduced. Use the existing [identity/resources commands](README.md#read-from-the-cli), passing `--credential-file` privately and a context actually returned by identity. Only the human reads `GET /api/v1/human/identity`, `GET /api/v1/human/resources`, `GET /api/v1/human/events` and `GET /api/v1/human/events/recent` are adopted; both event reads are metadata-only. The identity response describes the authenticating source; with other tenant sources, `contexts_complete=false` means their memberships remain unknown. Cross-source context selection is refused. A resource page carries its real durable `read_receipt`; a candidate digest never supplies identity, permission or a receipt.

The Journal's recent read is metadata-only. A successful page with `stream_mode:"snapshot_only"` and `live_cursor:null` identifies this current owned profile; the marker grants no permission and says nothing about another server/profile. Older-page cursors retain their authorized selection and fixed descending bound. The UI shows the actual read time and receipt of the last page read. Live updates, content, event detail and export remain unavailable for this profile even when their permissions appear in the access projection. After a successful Journal page identifies this profile, Content (Contenu) and Export (Exporter) explain this profile limit and are disabled; the granted permissions remain unchanged.

Use **Actualiser** (Refresh) to read recent events again. The Journal opens no stream, retry loop or periodic polling; returning to the tab retains the normal one-time revalidation. A failed revalidation withdraws displayed snapshot data, receipts and pagination positions. A transient error in the same context keeps the previously established restrictive profile; an identity/context/authorization change or session close clears that fact. A503 never establishes another profile. An explicitly refused content request remains an error with an explicit route back to Resources; there is no silent metadata fallback. Update gateway and dashboard together. The dated software evidence at the start of this guide retains its original two-read scope.

Known unadopted human, control, workload, broker, relay and OIDC methods, including event detail, export and stream, return explicit503 coverage refusals before legacy extractors, body handling or Store work. OIDC selected in the manifest remains selected and retained, while its handlers/bearers are closed. It is never reported as disabled. Only when OIDC is absent are the existing disabled status/profile GETs admitted. Health reads memory state; it is not proof that every source is available. These reads enable no modern approval, launch, network permission or egress control.

A busy mutex or SQLite writer in sourceA does not trigger SQL queries in A while authenticating and reading sourceB. A busy own source returns503. Busy is not absence or a permanent mismatch. Actual compared filesystem/configuration/marker/incarnation mismatches retain global owner invalidation. Filesystem revalidation still covers the full union: blocked filesystem calls or a shared Write epoch carry the existing availability limits. The private candidate index is bounded at65536 entries/16MiB of representation before accumulation; overflow refuses complete publication. These bounds do not measure process RAM.

For the adopted human reads, runtime compares the own source's real identity authorization revision and workload-binding-history high watermark before and after the adopted operation. These markers cover identity mutations and workload-binding issue/rotation/revocation; ordinary read audits do not move them. A compared mismatch requires discovery rebuilding with admission closed. This is not a universal writer generation: other HTTP writers remain closed, and a raw neighboring storage mutation cannot be detected instantly without observing that neighbor.

## Candidate A0: reserved technical control diagnostic

**A0 candidate contract, 13 November 2026: code and JSON Schema aligned; targeted software validation on `0114013`: 37 tests passed with no failures or ignored tests, and compilation and all-target checking passed.** These software results do not qualify runtime isolation or production deployment. The human-metadata validation already linked in this guide keeps its original source and scope; it is not A0 evidence. Existing startup commands and configuration files above are unchanged.

The candidate adopts only the existing exact GET `/control/api/v1/control/protocol` on the reserved transport, with no query or new startup flag. It requires a real technical `runner` entry in the retained `ReviewCredentialRegistry`, a unique technical candidate in the complete startup index and the real binding/source/namespace/generation. A named human bearer, a viewer, a workload credential, `HumanSourceAccess` or a DTO cannot supply that actor identity. Public GET `/api/v1/control/protocol`, HEAD on this diagnostic and known owned mutations remain closed; unknown paths/methods keep 404/405.

The checked `Business` transaction verifies the binding before facts and revalidates it before commit on the selected Store. Credential, source and epoch are revalidated before publication. Accepted usage and operation/IO permits stay with the real work until it finishes, including after the HTTP future is abandoned; this behavior is covered by the targeted software validation. Own-source contention refuses without waiting; the previous SQLite timeout is restored, with no neighboring SQL or legacy fallback. A0 provisions no credential or binding and adds no operator command, service, SQLite format, audit record or receipt.

The candidate Rust validator and JSON Schema agree on the existing `ControlProtocolV1` facts for formats 14/15; `active` remains the actual lease fact. A future 200 from `AuditClient::control_supervision_identity` would qualify neither broker lifecycle nor a connection permit. The broker 3–13 and relay 6–13 gates stay unchanged; 14/15 still encounter `IncompatibleControl` before broker effects. No worker, human launch or egress capability is opened.

Coverage is the complete W0 startup index plus the selected source's own generation, not multiprocess coherence or a universal writer generation. Owned HTTP writers remain closed. Real internal source/`WriteEpoch` writers remain available, with no post-startup server caller connected in the inspected source. A future writer changing credentials, workloads or candidate coverage must close admission through `require_rebuild` **before the effect**, then reconstruct the complete union. A B read cannot infer a new A collision without a global invalidation producer; the real own binding is nevertheless checked on each diagnostic. See the [candidate API contract](../../api.md#owned-control-a0). These are limits to preserve before adopting any writer, not a new end-user procedure.

The server reserves a cleanup supervisor before fallible builders/binds. Shutdown and Drop close human/context admission, stop HTTP, observe real HTTP joins, and wait for accepted/queued blocking usages and epochs. A drain error reports failure, including any primary bind/serve error. An unestablished drain is never success; real remaining usage/epoch handles retain their owner and file descriptors. Runtime/process termination and host failure remain outside this in-process guarantee.

Local browser `HumanApiClient.close()` clears the token, aborts requests and discards late responses. It does not revoke the durable credential. Modern credential mutation, fresh discovery of memberships from other sources and SSO sessions/revocation remain mandatory open work. The adoption workflow records its software results and [remaining qualification limits](../human-sources-maintenance/README.md#validation-scope). Stop consumers and retain configuration, databases, backups and evidence before operator reconciliation; never delete history to recover a green startup.
