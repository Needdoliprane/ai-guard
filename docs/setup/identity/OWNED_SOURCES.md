# Owned human sources: local identity and resources

This explicit gateway mode reopens an existing complete owned source union. The default remains `legacy`. Software validation of this change is **NOT_RUN** until the frozen source is admitted to QA; it does not qualify production, a container runtime or OIDC.

The operator must already hold a real private closure manifest, matching technical credential envelope, the existing tenant registry, Store14/15 databases and, when selected, AuthLedger5 plus OIDC configurationV2 and its public trust bundle. This change does not supply the offline producer of that manifest/envelope. The existing public single-database migrations stop at Store13/Auth4. Do not hand-author receipts, initialize replacement databases, increase their accepted version or use test fixtures as an installation procedure. Provision named people and grants before conversion using the supported offline identity procedure; the complete owned bootstrap remains an explicit delivery gap.

For an installation whose retained manifest/envelope were produced through the real owned migration protocol, add these options to its existing containerized gateway launch, retaining its actual policy, data mounts, event limit and other options:

```text
gateway --human-source-mode owned_sources
  --tenants-file /control/tenants.json
  --human-sources-manifest /control/existing-closure.json
  --human-credentials-envelope /control/existing-technical-credentials.json
  --human-control-config-revision <actual-positive-control-revision>
```

These are references to existing private files, never tokens in arguments. The manifest and envelope are not generated by startup. The tenant registry supplies effective quotas and policies. The loader independently resolves defaults and recalculates the version1 public configuration digest, excluding credentials, their digests and private paths; physical bindings are compared separately. Use the revision retained by the operator, not a value guessed from an error. An OIDC installation also requires its existing `--oidc-config` and explicit `--human-oidc-mapping-revision`; that positive closure revision is distinct from the string `mapping.revision`. Missing/changed files, limits, revisions, formats or union refuse startup. Initialization flags conflict with this mode. Preserve all files and known commits on failure; startup performs no migration, reset or legacy fallback.

Use the matching trusted dashboard launch profile:

```text
dashboard --shared-tenants --human-source-mode owned_sources
  --upstream http://gateway:8787 --front-dir /app/front
```

Keep the installation's actual internal upstream and static directory. A viewer-file fallback conflicts with this profile. Gateway authorization remains authoritative even if presentation is misconfigured. Modern HEAD requests are refused before viewer verification or conversion to GET.

The admitted human credential is the already provisioned private local bearer. The first `human identity` GET is its connection check; no password/login endpoint is introduced. Use the existing [identity/resources commands](README.md#read-from-the-cli), passing `--credential-file` privately and a context actually returned by identity. Only `GET /api/v1/human/identity` and `GET /api/v1/human/resources` are adopted. The identity response describes the authenticating source; with other tenant sources, `contexts_complete=false` means their memberships remain unknown. Cross-source context selection is refused. A resource page carries its real durable `read_receipt`; a candidate digest never supplies identity, permission or a receipt.

Known unadopted human, control, workload, broker, relay, event and OIDC routes return explicit503 coverage refusals before legacy extractors, body handling or Store work. OIDC selected in the manifest remains selected and retained, while its handlers/bearers are closed. It is never reported as disabled. Only when OIDC is absent are the existing disabled status/profile GETs admitted. Health reads memory state; it is not proof that every source is available. No modern approval, launch, network permission or egress control is enabled by these two reads.

A busy mutex or SQLite writer in sourceA does not trigger SQL queries in A while authenticating and reading sourceB. A busy own source returns503. Busy is not absence or a permanent mismatch. Actual compared filesystem/configuration/marker/incarnation mismatches retain global owner invalidation. Filesystem revalidation still covers the full union: blocked filesystem calls or a shared Write epoch carry the existing availability limits. The private candidate index is bounded at65536 entries/16MiB of representation before accumulation; overflow refuses complete publication. These bounds do not measure process RAM.

Runtime compares the own source's real identity authorization revision and workload-binding-history high watermark before and after the adopted operation. These markers cover identity mutations and workload-binding issue/rotation/revocation; ordinary read audits do not move them. A compared mismatch requires discovery rebuilding with admission closed. This is not a universal writer generation: other writers remain closed, and a raw neighboring storage mutation cannot be detected instantly without observing that neighbor.

The server reserves a cleanup supervisor before fallible builders/binds. Shutdown and Drop close human/context admission, stop HTTP, observe real HTTP joins, and wait for accepted/queued blocking usages and epochs. A drain error reports failure, including any primary bind/serve error. An unestablished drain is never success; real remaining usage/epoch handles retain their owner and file descriptors. Runtime/process termination and host failure remain outside this in-process guarantee.

Local browser `HumanApiClient.close()` clears the token, aborts requests and discards late responses. It does not revoke the durable credential. Modern credential mutation, fresh discovery of memberships from other sources, SSO sessions/revocation and the offline operator bootstrap remain mandatory open work. Stop consumers and retain configuration, databases, backups and evidence before operator reconciliation; never delete history to recover a green startup.
