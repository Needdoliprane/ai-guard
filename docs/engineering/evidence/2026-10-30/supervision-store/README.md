[Implémentation](implementation.md), [tests](tests.md), [revue finale](review.md), [artefacts](artifacts.md).

Les RED conservés démontrent : authority opaque acceptée à tort par le nouveau protocole, ancien succès d'import masquant un mismatch ultérieur, puis seconde permission dans une copie SQLite pré-claim. Corrections : UUID exigé uniquement par la nouvelle admission, mismatch persistant/pending bloquant, et capacité d'exécution privée non sérialisée. Celle-ci exige une origine créée ici et migrée avant toute autre activité ; namespace, identité backing et tête initiale sont retenus. Ouverture indépendante, copie ou restauration : maintenance, aucune nouvelle émission. Les connexions sœurs partagent un watermark monotone sous mutex jusqu'au commit et à sa publication. Le rollback live testé garde le même inode et invalide toutes les sœurs.

Le fresh bind d'un legacy Created est refusé avant append : aucun parcours de reprise n'est simulé. Diagnostic structurel d'une base malsaine et tête forensic restent accessibles selon les contrôles de backing/schéma, sans réactiver l'autorité ou diminuer le watermark. Les quatre échecs de régression diagnostic (un integrity, trois head), leur correction et le dernier verrouillage sont conservés dans les rapports.
