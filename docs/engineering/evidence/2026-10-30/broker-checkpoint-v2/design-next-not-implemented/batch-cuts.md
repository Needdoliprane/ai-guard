# Coutures minimales du premier batch permanent

Propositions sur V2 gel3 ; lecture seule, aucun Cargo/code ajouté. Root garde IPC/auth/protocole/CLI, writer et ordonnanceur. Les noms des deux handles root ci-dessous restent à figer, sans nouvelle couche réseau.

**1. Préparer seulement une nouvelle soumission.** Dans `src/runner.rs` : `prepare_broker_submission(options: RunOptions, operation_id: Uuid) -> Result<PreparedSubmission>`. Factoriser choose_plan pour recevoir l'opération imposée ; refuser approve_hash ici, la revue étant une opération IPC séparée. Session/binding nouveaux seulement après reserve=New. PreparedSubmission garde le RunPlan privé et les FD nécessaires ; getters intention, binding-kind/source et checkpoint initial. Réutiliser prepare/freeze_provider_credential et les parseurs purs. Root fait reserve puis préparation puis accept durable avant décision/admission/runtime. Accepted rejoué ne repasse jamais par choose_plan, source ou Auto. Aucun changement du run historique.

**2. Reconstruire le contexte privé.** Nouveau `src/runner/broker.rs`, seul propriétaire runner avec les coutures de visibilité nécessaires dans runner/managed.rs : `BrokerRunState::from_job(job: &AcceptedJobV1) -> Result<Self>` pur, puis credentials depuis job.binding_source durable uniquement. Reconstituer le vrai RunPlan à partir intention + payload courant, sans reset d'approbation ; aucun write sessions.json concurrent. Réutiliser approved_runtime, prepare/reopen_authority, worker_spec, inspection/observation_dto, workspace::prepare_workspace_excluding et scanner/diff. Le managed préparatoire conserve manifest/archive et admission pending avant RPC ; V2 distingue maintenant requested/admitted. Le manifeste journal fournit l'UUID manuel déjà figé et son handoff digest.

**3. Exécuter par étapes V2.** API proposée : `execute_broker_batch(job, client: AuditClient, writer: &CheckpointWriter, stops: &PrearmedStops) -> Result<RunSummary>`, async. Le client est celui du contexte fraîchement authentifié root ; aucun read_token de secours. Writer est le handle concret du writer root, pas un appel direct à Journal depuis l'ordonnanceur. Chaque requête réelle naît pending, commit confirmé, RPC typé, puis ACK en révision suivante ; CAS garde son identité.

Ordre obligatoire : Decision/revue → copie filtrée et managed préparatoire → SupervisedAdmission → Prepare → helper Import → helper ImportVerification avec tar réel/scanner et manifeste égal → CreateIssued → worker Created → arm/claim → terminal engagé → FinalScan. Export explicite : ExportRequest durable, destination neuve, helper Export. Réutiliser helper_execution_policy_v1, ContainerSpec::with_operation/with_managed_names et ManagedRuntime::execute_retained ; ne pas rappeler import_workspace/managed_archive legacy, qui émettent directement sans les nouveaux claims. Les vrais reçus déterminent les permissions ; aucun argv helper fourni par IPC.

**4. Couture callback runtime.** `on_created` conserve owned, persiste Arm pending, obtient/revalide ArmResult, installe immédiatement la cible auprès de stops, persiste le reçu, puis claim pending/RPC/ACK et recheck horloge/registration avant EmitOnce frais. Réutiliser le callback FnOnce existant ; replay reste ObserveOnly. Le scheduler root possède runtime ancré + CID/config/clock immuables, slots réservés et résultat borné ; aucun accès PlanState, writer, HTTP ou clé fournisseur pour son stop_snapshot_owned.

**Blocages précis avant preuve réelle.** BrokerRunState/credentials durables et handles writer/stops n'existent pas encore. Les RPC legacy doivent être remplacés par les routes3, sans désactiver fresh-origin/maintenance. Le monitor legacy refresh écrit toutes500ms : ne pas le reprendre. execute_created porte encore Ctrl-C global, durée locale et timed_out local ; isoler le signal de session du broker et reporter le vrai résultat du scheduler, sans nouvelle durée après reprise. Toute petite couture runtime nécessaire appartient exclusivement à l'intégrateur runtime, pas à l'IPC. D5 reste incertain : Created/absence/kill/rm ne libèrent jamais quota. Aucun cutover par défaut avant helpers/batch/TTY qualifiés ; première preuve Docker : A1/A2/B1, CLI SIGKILL, effet après mort puis arrêt ciblé à deadline, témoin intact, audit/usage uniques.
