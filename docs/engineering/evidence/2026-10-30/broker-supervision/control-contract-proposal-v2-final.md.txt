## BPR-01: a routing hint is never an authorization

The startup digest index only selects one configured backend origin. Before **every new IPC action**, including status/approve/stop/export, authenticate the **presented** credential freshly against that backend and require the current runner role, expected tenant and control namespace. Do this before profile/job lookup, source/binding access or RPC dispatch. Gateway failure/revocation/role change refuses the new action; no stale positive cache, alternate origin/profile or runner-file substitution is tried.

The resulting opaque action context owns that exact credential and immutable principal; RPC construction uses it, never `configRoot/secrets/runner`. It is not serializable or stored in jobs and is not reused for a later frame. Each mutation RPC still authenticates that same credential at the gateway. This is freshness at the authenticated action boundary, not an atomic promise against revocation between two machines' instructions.

Autonomous recovery has a **different** authority: an already durably admitted job binds origin/tenant/namespace/installation/intent and its immutable profile. Recovery may refresh a current runner reference only after reauthenticating it to that same identity, and never to serve a new caller, authorize a new submission/destination or replace a missing approval. A merely accepted pre-admission submission cannot borrow this recovery grant. The prearmed stop needs no credential; revocation does not suspend it.

Illustrative concrete ownership declarations for the future IPC module (private constructors must enforce the flow above):

## BPR-02: closed import verification, separate from final scan

Purpose/policy1 commands are fixed in shared Rust: Import uses the current tar extract argv (`--no-same-owner`, `--no-same-permissions`); ImportVerification/FinalScan/Export use current tar-create argv. Same immutable image/parent volume, network none, no credentials, preset2 and existing bounded helper resources; deadline120s independent of the worker's timeout. No arbitrary API helper argv.

Import permission resolves an accepted parent admission and requires Preparing/quota held/no worker start. **ImportVerification** resolves the precise import helper/arm and a centrally recorded credible successful terminal observation for that helper; parent must still be Preparing, quota held, no worker create/start claim, and permission manifest must equal the admitted workspace manifest. Revalidate these facts at **claim**, not just arm. Parent/source/CID/purpose/permission divergence refuses; no repeated import start is granted.

The verification helper has its own arm, claim, clock, observations and cleanup. Preserve `recover_import`'s safe archive parsing and exact `checkpoint.before` comparison before proceeding. An exit0 alone is not import completion. A report with a well-formed but different observed manifest is recorded as mismatch and blocks continuation; no report leaves verification unknown. Gateway validates reported bindings/digests, not the filesystem independently. FinalScan and Export continue to require a credible terminal parent. Export also resolves the actual durable ExportRequest, whose opaque destination UUID and hash bind a private immutable destination intent **persisted before ACK**; a rotated path under that UUID conflicts.

Every helper route compares `{worker_id}` from the URL with the loaded arm/permission/job in the authenticated Store, even when the DTO contains only `helper_id`. Helper record IDs, parent attempt, namespace and all receipt fields must agree. Reuse of an unrelated same-tenant receipt is not authorization. Subject keys remain derived: worker/import per attempt; import_verification/final_scan/export per helper UUID. A replay never changes an arm deadline or re-emits a claim.

## BPR-03 and shared runtime boundaries

Use the coordinated snapshot-first stop port: inspect and compare full Created snapshot/fingerprint/image/resources/name/CID, then revalidate authority **before** kill. Divergence/missing inspection gives Unknown without kill; post-effect observation is validated again. The remaining administrative race is a trust-boundary limit, not an atomic engine attestation. A stopped Created is not an allocation or a proof against an old start RPC.

Before the one non-clonable emission permit is consumed, perform the last real host-clock read **after** Command construction/FS checks and TTY preparation; no subsequent await/preparation I/O may restart or consume the deadline unnoticed. Potentially blocking executable verification/inspect/stop run in isolated bounded effect capacity, not the scheduler tick. A stuck A must not consume B's reserved stop capacity; cancellation/timeout does not prove an underlying syscall ended.

## Final helper seam agreed by root

Implement shared `helper_execution_policy_v1(parent: &WorkerV1, purpose: HelperPurposeV1, helper_id: uuid::Uuid) -> anyhow::Result<HelperExecutionPolicyV1>`. Gateway and broker independently derive the same strict policy above: exact parent bindings/name/image/volume, fixed tar argv, cwd `/workspace`, network none, preset2 even for a TTYv3 parent, CPU2000/memory1073741824/PID256/timeout120/restartNo and no credentials. Its hash domain is `ai-guard:helper-execution-policy:v1`; helper `ArmV1.inspection.spec_hash` must equal **this** derived hash, never the worker spec hash or an arbitrary caller value. Worker arms keep the worker spec hash. Fresh supervised admissions reject FixedSandboxV1; historical plan numbering/hashes remain unchanged. Store metadata uses an identity-free `SupervisionStateV1`; only the API enriches its output with authenticated tenant/role.
